# Bear Charter and Cabinet Missions

A Bear's **charter** is its durable purpose and responsibility boundary. A Cabinet **Mission** is a shared work and knowledge container that may involve one or more Bears.

They are related but not the same thing.

## Summary

- a charter is a property of a Bear, not a separate entity
- a Bear organizes work through domains, work surfaces, projects, routines, tasks, and memory
- a Cabinet Mission is a shared cross-Bear container for work and knowledge
- if you need a separate identity, policy boundary, or memory boundary, you likely need another Bear

## Bear charter

A charter answers:

- why this Bear exists
- what responsibility boundary it owns
- what kinds of knowledge, work, and tools are in scope

Examples:

- care for the house
- build and operate the SaaS product
- coordinate executive administrative flow

## Bear-scoped organization

Useful Bear-level concepts include:

| Concept | Meaning |
|---------|---------|
| Domain | durable area of responsibility or knowledge |
| Work surface | durable context for related work |
| Project | bounded initiative with a desired outcome |
| Routine | recurring responsibility |
| Task | executable work unit |
| Run | one execution attempt |

## Work surfaces vs Missions

A work surface is the durable context the Bear is acting on.

A Cabinet Mission is a shared container that may span multiple work surfaces and multiple Bears.

Examples:

- one Mission may involve several repositories, deployments, and projects
- one work surface may exist without any Cabinet Mission at all
- one Bear may participate in several Missions while retaining one charter

## When to create another Bear

Create another Bear when the responsibility needs a separate:

- assistant identity
- memory boundary
- membership or privacy boundary
- tool/capability profile
- autonomy or policy boundary
